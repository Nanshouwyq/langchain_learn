# RAG 核心概念（RAG_concepts）

**标签**: RAG, LLM, 检索

RAG（Retrieval-Augmented Generation，检索增强生成）让大模型先检索外部知识，再基于检索结果生成回答，从而降低幻觉、支持私有知识更新。本文按「概念—流程—组件—策略—评估—落地」整理，便于笔记检索与复习。

---

## 一、是什么、解决什么问题

| 概念 | 英文 | 说明 |
|------|------|------|
| RAG | Retrieval-Augmented Generation | 检索 + 生成的组合范式 |
| 参数知识 | Parametric Knowledge | 模型训练时学进权重的知识 |
| 非参数知识 | Non-parametric Knowledge | 外挂在向量库/文档库中的知识 |
| 幻觉 | Hallucination | 模型编造看似合理但不真实的内容 |
| 知识更新 | Knowledge Update | 改文档/重建索引即可更新，无需重新训练模型 |

**典型要解决的问题：**

1. 让回答基于公司文档、笔记、手册等私有资料  
2. 提供可追溯引用（来源、页码、片段）  
3. 降低纯 LLM 闭卷回答的幻觉  
4. 比微调更低成本地接入新知识  

---

## 二、标准流水线（端到端）

```text
【离线 / 入库】
数据源 → 加载 → 清洗 → 切分 → Embedding → 写入向量库（+ metadata）

【在线 / 问答】
用户问题 →（可选改写）→ Embedding → 检索 Top-K →（可选重排）
        → 拼进 Prompt 作为 context → LLM 生成 → 答案（+ 引用）
```

| 阶段 | 目标 |
|------|------|
| 入库 | 把知识变成可检索的块 |
| 检索 | 找到与问题最相关的块 |
| 增强 | 把块作为上下文约束生成 |
| 生成 | 产出最终自然语言答案 |

---

## 三、核心组件概念

| 组件 | 英文 | 作用 |
|------|------|------|
| 文档 | Document | 原始知识单元（正文 + 元数据） |
| 切分块 | Chunk | 检索与向量化的基本片段 |
| 嵌入模型 | Embedding Model | 把文本映射到向量空间 |
| 向量库 | Vector Store | 存储向量并做相似度搜索 |
| 检索器 | Retriever | 给定问题返回相关块 |
| 重排器 | Reranker | 对初检结果二次精排 |
| 提示词模板 | Prompt Template | 规定如何使用 context 回答 |
| 生成模型 | Generator / LLM | 基于上下文生成最终答案 |
| 引用 | Citation / Source | 标明答案依据的文档片段 |

---

## 四、Document、Chunk 与 Metadata

| 概念 | 定义 |
|------|------|
| `page_content` / text | 真正参与 embedding 与回答的正文 |
| metadata | 每条块的标签：来源、标题、类别、页码等 |
| chunk_size | 块大小（字符/token），影响上下文完整度 |
| chunk_overlap | 块重叠，减轻关键句被切断的问题 |

**切分过碎：** 上下文不完整，答案片面。  
**切分过粗：** 噪声多，检索不准，也浪费上下文窗口。

---

## 五、Embedding 与相似度

| 概念 | 说明 |
|------|------|
| 向量 | 文本的稠密数值表示 |
| 语义相似 | 意思接近的文本，向量距离更近 |
| 余弦相似度 | 常用相似度度量之一 |
| 查询向量 | 用户问题经过同一 Embedding 模型得到 |
| 模型一致性 | 入库与查询必须用**同一套** Embedding，换模型需重建索引 |

---

## 六、检索方式

| 方式 | 英文 | 思路 | 特点 |
|------|------|------|------|
| 向量检索 | Dense Retrieval | 语义向量近邻搜索 | 擅长同义改写、语义匹配 |
| 关键词检索 | Sparse / BM25 | 词项匹配打分 | 擅长专有名词、精确关键词 |
| 混合检索 | Hybrid Search | 稠密 + 稀疏融合 | 实际系统常更稳 |
| 元数据过滤 | Metadata Filtering | 先按标签缩小候选 | 如只搜某类别/某目录 |
| Top-K | Top-K | 取前 K 个最相关结果 | K 太小易漏，太大易噪 |

---

## 七、重排与上下文组装

| 概念 | 说明 |
|------|------|
| 初检 | 用向量/关键词快速拉回较多候选（如 20–50） |
| 重排 | 用交叉编码器等更强模型精排，再取 Top-K |
| 上下文窗口 | LLM 一次能接收的最大 token 限制 |
| 上下文压缩 | 摘要或抽取关键句，减少无关文本 |
| 拼接顺序 | 常按相关度或文档结构排列后塞进 Prompt |

**常见 Prompt 约束：**「仅根据下列上下文回答；上下文没有则说明不知道。」

---

## 八、RAG 常见架构变体

| 模式 | 说明 | 适用 |
|------|------|------|
| Naive RAG | 检索 Top-K → 直接生成 | 入门、语料干净 |
| Advanced RAG | 加查询改写、混合检索、重排、更好切分 | 生产常用 |
| Modular RAG | 检索/路由/工具可插拔组合 | 复杂业务 |
| Graph RAG | 引入知识图谱关系 | 多跳关系推理 |
| Agentic RAG | Agent 决定是否检索、检索什么、是否再搜 | 多源、多步任务 |

---

## 九、查询侧优化概念

| 技巧 | 英文 | 作用 |
|------|------|------|
| 查询改写 | Query Rewriting | 把口语问题改成更利检索的写法 |
| 多查询 | Multi-Query | 生成多个改写分别检索再合并 |
| HyDE | Hypothetical Document Embeddings | 先让 LLM 写假设答案再向量检索 |
| 子问题分解 | Sub-Questioning | 复杂问题拆成多个检索子任务 |
| 路由 | Routing | 按问题类型选择不同知识库/策略 |

## 十、生成侧关键概念

| 概念 | 说明 |
|------|------|
| 上下文接地 | Grounding：答案应能在 context 中找到依据 |
| 拒答 | 检索不足时明确说「资料中没有」 |
| 引用展示 | 返回答案时附带来源路径或原文片段 |
| 温度 | 知识问答通常用较低 temperature，更稳 |

---

## 十一、评估指标（概念层）

| 维度 | 关注点 | 常见指标/方法 |
|------|--------|----------------|
| 检索质量 | 相关块有没有被找回 | Recall@K、MRR、nDCG |
| 答案忠实度 | 是否背离上下文胡编 | Faithfulness、人工抽检 |
| 答案相关性 | 是否回应用户问题 | Relevance 评分 |
| 端到端 | 用户是否满意 | 点赞点踩、A/B、任务成功率 |
| 引用正确性 | 引用来源是否真支撑结论 | Citation Precision |

> 只看「答案好不好读」不够，RAG 还要看「检索对不对、有没有瞎编」。

---

## 十二、和微调 / 纯提示的对比

| 方案 | 优点 | 局限 |
|------|------|------|
| 纯 Prompt | 简单 | 难承载大量私有知识，易幻觉 |
| 微调 | 可改风格/格式/领域表述 | 成本高，知识更新慢，仍可能幻觉 |
| RAG | 知识可更新、可引用、成本相对低 | 依赖切分与检索质量；多跳推理更难点 |

三者可组合：微调管风格与格式，RAG 管事实知识。

## 十四、常见失败模式与对策

| 现象 | 可能原因 | 处理方向 |
|------|----------|----------|
| 答非所问 | 检索不准 | 改切分、混合检索、重排、查询改写 |
| 胡编 | Prompt 未约束 / 检索空 | 强制依据上下文、允许拒答 |
| 答案片面 | Top-K 太小或块被切裂 | 增大 K、增加 overlap、句子窗口 |
| 上下文爆炸 | K 太大或块太长 | 重排、压缩、限制 token |
| 换模型后变差 | Embedding 不一致 | 重建向量库 |
| 中文检索弱 | Embedding 不适合中文 | 换中文效果更好的向量模型 |

## 十五、易混概念

| 对比 | 区别 |
|------|------|
| 检索 vs 生成 | 找证据 vs 写答案 |
| Embedding vs Chat 模型 | 向量化 vs 对话生成，职责不同 |
| Chunk vs Document | 检索单元 vs 原始文档（可一对多） |
| Top-K vs 重排 | 粗召回 vs 精排序 |
| metadata 过滤 vs 向量相似 | 结构化约束 vs 语义相近 |
| RAG vs Agent | 固定检索生成 vs 动态决定是否/如何检索与用工具 |

## 十七、落地检查清单

1. 入库与查询是否同一 Embedding 模型  
2. chunk_size / overlap 是否做过简单试验  
3. Prompt 是否明确「仅根据上下文回答」  
4. 是否返回并检查来源片段  
5. 空检索时是否有拒答策略  
6. 是否用真实问题集做 Recall 与人工抽检
